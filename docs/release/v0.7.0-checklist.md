## 7. What publishing would take, and was not done

Listed so that publication is one deliberate decision rather than a sequence someone has to
reconstruct:

1. bump the version in all six declarations and `package-lock.json`, and add `## [0.7.0]` to
   `CHANGELOG.md` above the retained `## [Unreleased]`;
2. run `npm run verify:release` on the frozen commit, with a real MongoDB and a Docker daemon, and
   record the result here;
3. create the annotated tag on the squash-merge commit of the release pull request;
4. create the GitHub release as a **pre-release**, with no assets, and mark nothing stable or
   latest;
5. record the publication in the post-release documentation pull request, as `v0.6.1` did.

**None of steps 1–5 was taken.** The version is still `0.6.1`, no tag exists, and nothing was
published anywhere.
