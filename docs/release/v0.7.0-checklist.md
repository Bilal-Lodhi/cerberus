### The harness was run in the shape CI does not, and that found a defect

The same harness was run through the `Release verification` **`workflow_dispatch`** — the manual
drill, rather than a pull-request job. It came back **18 passed, 1 failed**: the attribution
guard.

The guard's default range was the literal `origin/main..HEAD`. That is true in a developer's
clone and true in `ci.yml`, which passes an explicit `--range` derived from the event, and
**false** in this workflow, whose `actions/checkout@v4` fetched one ref and no remote-tracking
branches. `git log origin/main..HEAD` exited 128 and the guard died with an unhandled
`execFileSync` stack trace. Only the manual drill ran in the shape that exposed it.

Both halves were fixed and re-run:

| | |
| --- | --- |
| The guard | Tries `origin/main`, then `main`, then `refs/remotes/origin/HEAD`, and exits non-zero with a **diagnosis** when none resolves. An unresolvable base is not "nothing to check": a guard that examined no commits would report OK, which is the one answer it must never give for a range it could not read |
| The workflow | `fetch-depth: 0`, so what the guard resolves is the whole range being released rather than the tip alone |
| The test | `apps/api/test/release/attribution-guard-range.test.ts` drives the guard as a process and asserts the exit code, the diagnosis and that the base is discovered. Verified against a faithful reproduction of the `actions/checkout` shape — `git init`, `remote add`, `fetch --depth=1 <sha>`, `checkout FETCH_HEAD`, no refs at all — where the guard now exits 1 naming the fix |
| **Re-run** | **`workflow_dispatch` on the fix branch: success — 19 passed, 0 failed, 0 skipped** |

The first version of that test asserted the default invocation always succeeds, which is the
guard's own mistake one layer up, and it failed in CI for being right. It now describes both
checkout shapes, because both are real.

## 9. What was deliberately not done

Recorded so the checklist cannot be read as "everything was attempted":

- **No cache.** The decision and its evidence are in
  [live-read-freshness-policy.md](../development/live-read-freshness-policy.md) §9.
- **No bounded live-list query.** Designed, measured, and deferred with the reason stated in
  [maturity-plan.md](../development/maturity-plan.md). The equivalence proof it needs does not
  exist yet, and a partial bound would make the read path less trustworthy.
- **No console change.** The polling defects are recorded in
  [console-polling-audit.md](../development/console-polling-audit.md) and are not server concerns.
- **No version bump and no changelog promotion.** Both belong to publication, which is a
  maintainer decision this cycle does not take.
