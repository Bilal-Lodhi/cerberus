# `v0.3.0` release checklist — **draft, every box unchecked**

> **Draft. Nothing has been executed.** No `v0.3.0` tag exists, no GitHub release was
> created, no package or image was published. Every gate below is a step to work through
> **when an owner authorises a release**, not a record of one that happened.
>
> The `v0.2.0` checklist is the precedent for the shape; this one is not a copy of it,
> because the gates a release needs depend on what changed.

## 0. Authorisation

- [ ] The owner has explicitly authorised publishing `v0.3.0`.
- [ ] The owner has decided the release **kind**: pre-release (as `v0.1.0` and `v0.2.0`
      were) or something else. Nothing in this repository assumes which.
- [ ] The owner has confirmed the **version number**. `0.3.0` is the recommendation in
      [development/architecture-integrity-checkpoint.md](../development/architecture-integrity-checkpoint.md);
      it is a recommendation, not a decision.
- [ ] The owner has confirmed what is **withheld**: marking it stable or latest, publishing
      npm or a registry image, deploying a hosted instance, moving the tag afterwards.

## 2. Local gates

- [ ] `npm ci` — clean.
- [ ] `npm run build` — clean.
- [ ] `npm run typecheck` — clean.
- [ ] `npm test` **with** `CERBERUS_TEST_MONGODB_URI` pointed at a disposable MongoDB —
      every test passes, **nothing skipped**.
- [ ] `npm test` without a database — the only skips are the ones with a stated reason.
- [ ] `npm run check:docs` — 0 broken links and 0 broken anchors.
- [ ] `cd apps/console && flutter pub get && flutter analyze && flutter test` — clean.
- [ ] `dart format --output=none --set-exit-if-changed .` — clean.
- [ ] `flutter build web --release` — succeeds, and writes `apps/console/build/web`.
- [ ] `npm audit --omit=dev --audit-level=high` — 0 vulnerabilities, **read rather than
      assumed**, because that CI job is advisory.
- [ ] `npm run bench` — run, and the numbers compared against
      [development/performance-baseline.md](../development/performance-baseline.md). A
      regression is investigated, not waived.

## 3. End-to-end gates that must be **re-run**, not assumed

- [ ] `docker build` succeeds.
- [ ] Compose starts the stack and `/health` answers.
- [ ] Startup fails closed without `CERBERUS_API_KEY` under `NODE_ENV=production`.
- [ ] `GET /ready` answers `503` when MongoDB is stopped, and `200` when it is up.
- [ ] **The migrations run against a real database that predates them.** Take a dump with
      duplicate risk assessments and a legacy `fullscreenExitCount`, apply `0002` and
      `0003`, and confirm: the duplicates are removed, the counter is renamed with the
      higher total preserved, and the ledger records both.
- [ ] **A restart against a real database** preserves counters, a lock, a termination and
      the terminal content.
- [ ] **A retried batch after a restart** is stored once and counted once.
- [ ] The backup and restore drill in
      [operations/backup-restore.md](../operations/backup-restore.md) — including the
      manifest count comparison.
- [ ] The console, against a running API, shows the new error text for a full corpus, an
      expired session and a terminated session.

## 4. Documentation gates

- [ ] `CHANGELOG.md` has a dated `[0.3.0]` section, moved out of `[Unreleased]`, and it
      matches what actually merged.
- [ ] [release/v0.3.0-release-notes.md](v0.3.0-release-notes.md) is reviewed and its
      "draft" banner removed.
- [ ] [development/architecture-integrity-checkpoint.md](../development/architecture-integrity-checkpoint.md)
      records the release target commit.
- [ ] `package.json` versions are bumped in the root, `apps/api` and `packages/mcp-mongodb`.
- [ ] `MCP_SERVER_VERSION` in `packages/mcp-mongodb/src/tool-names.ts` is bumped.
- [ ] [compatibility.md](../compatibility.md) reflects the new public surface: the added
      MCP arguments, the new error codes, the deprecated aliases and the new collection.
- [ ] [development/maturity-plan.md](../development/maturity-plan.md) marks the phase
      complete and names what the next cycle should consider.
- [ ] Every document in `docs/` is listed in [index.md](../index.md).
- [ ] `npm run check:docs` passes **after** the version bump, not only before it.

## 5. CI gates

- [ ] Every required job is green on the release commit: TypeScript, Flutter console,
      Docker build, Secret scan, and **Integration (real MongoDB)**.
- [ ] The Dependency audit job has been **read**, not merely observed to be green — it is
      `continue-on-error` on purpose.
- [ ] No check was skipped, bypassed or weakened to make the release pass.

## 6. Publication

- [ ] The tag is **annotated**, not lightweight, matching `v0.1.0` and `v0.2.0`.
- [ ] The tag is created **after** the release commit is on `main`, and is never moved.
- [ ] The GitHub release body is the release notes, and the limitations section is included
      **verbatim** rather than summarised away.
- [ ] The release is marked as the owner authorised, and no more.
- [ ] No npm publish, no registry push, no deployment.
- [ ] `v0.1.0` and `v0.2.0` are re-verified **after** publication.

## 7. After publication

- [ ] `CHANGELOG.md` `[Unreleased]` is opened again with a placeholder.
- [ ] The next maturity cycle's charter is written, or the project is declared paused.
- [ ] Any limitation this release documented is either carried into the next charter or
      explicitly accepted again.
