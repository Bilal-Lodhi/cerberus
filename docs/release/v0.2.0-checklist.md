## 2. Release material audit

The audit looked for text that would become false on publication, and for claims the
software does not support. It found real problems, which is why a release-fix PR
preceded the tag.

**Corrected before tagging:**

| Finding | Action |
| --- | --- |
| The release notes were headed `(DRAFT, NOT PUBLISHED)` and said "Nothing here has been published" — false the moment it becomes the release body | Retitled and rewritten as a publication record |
| All 13 internal links in the release notes were repo-relative, so they would not resolve on the GitHub release page | Converted to absolute URLs pinned to `v0.2.0`; every target verified to exist |
| `SECURITY.md` said "There is no rate limiting and no replay protection beyond TLS" — rate limiting now exists | Rewritten to describe the limiter accurately, including that it is a per-process backstop that deliberately does not limit unauthenticated requests |
| `SECURITY.md` said "Session state lives in process memory and is lost on restart" — counters and lifecycle are now durable | Rewritten, with a pointer to the session-state model |
| `SECURITY.md` said "There is no overlap window" for rotation — an overlap now exists | Rewritten with the four-step procedure |
| `README.md` listed "Durable session state … lost on restart" under *not implemented* | Removed; replaced with the items that genuinely remain absent |
| `README.md` bundled replay protection and automated rotation into one line | Split, with retry idempotency distinguished from replay protection |
| `README.md` status banner said `0.1.0` | Updated to `0.2.0` |
| `maturity-plan.md` carried three stale accepted-limitation rows | Rewritten to match what the code does |
| `CHANGELOG.md` said the release material "are drafts and nothing in them has been executed or published" | Corrected |
| `docs/compatibility.md` said `v0.1.0` "is the only published release" | Corrected |

**Confirmed absent** (checked, not assumed): unsupported production-readiness claims,
compliance claims, endpoint-agent claims, user-attribution claims, any claim that rate
limiting is DDoS protection, any claim that retry idempotency equals anti-replay, any
universal benchmark claim, any claim that similarity proves exfiltration, secrets, and
local filesystem paths.

Accepted limitations are explicit in the release notes, the threat model, the README
roadmap and the maturity plan. Migration impact, key rotation and readiness semantics
were each re-read against the code.

**A defect found and fixed during this verification.** `docker-compose.yml` did not
forward `CERBERUS_API_KEY_PREVIOUS`, `CERBERUS_MCP_TOKEN_PREVIOUS`,
`CERBERUS_RATE_LIMIT_ENABLED` or `CERBERUS_AI_REQUESTS_PER_MINUTE` into the container,
so an operator running the documented Compose stack **could not use the rotation
overlap or tune the limiter at all** — the variables were silently ignored. The first
attempt at this check is what exposed it: the banner reported `previousApiKey=unset`
with the variable set. Fixed, and re-verified:

```
overlap active:  current-key -> 200   retired-key -> 200   other -> 401
                 banner: previousApiKey=set
overlap ended:   current-key -> 200   retired-key -> 401
                 banner: previousApiKey=unset
```

One note, not a defect: Docker's own healthcheck still read `healthy` briefly during
the MongoDB outage. That is its retry configuration (3 failures at a 15 s interval),
not a stale result — the API's `/ready` reported `503` immediately.

## 6. Real OpenAI call decision

**No fresh live call was made, and none was necessary.**

The provider boundary did not change in this release: no change to how requests are
constructed, no model or configuration change, no change to the parser/provider
boundary. The live evidence gathered during the phase therefore remains
representative, and the instructions require a fresh paid call only when one of those
has changed. Making one for ceremony would spend money to re-establish a fact that did
not move.

The provider boundary is covered by deterministic tests with a stubbed provider, which
is what CI runs.
