# Cerberus v0.2.0 — release checklist (DRAFT)

> **Status: draft. Nothing here has been executed.**
>
> Every box is unchecked on purpose: this is the list a maintainer works through
> *when authorising a release*, and pre-ticking it would defeat the purpose. The
> `v0.1.0` equivalent, with the evidence recorded for each gate, is
> [release-checklist.md](release-checklist.md).

## 0. Authorisation

- [ ] The maintainer has explicitly authorised publishing `v0.2.0`.
- [ ] A decision has been made on **stable vs pre-release**. `v0.1.0` was published
      as a pre-release, and nothing in `v0.2.0` changes the project's maturity
      enough to make that decision automatic.
- [ ] A decision has been made on **what, if anything, is published**: a GitHub
      Release only, or also an npm package and a container image. `v0.1.0` published
      none of the latter.
- [ ] The licence has not changed. (Apache-2.0; no change is proposed.)

## 1. Freeze

- [ ] `main` is green on the commit being released, on every required check:
      TypeScript, Flutter, Docker build, Secret scan, and the advisory dependency
      audit.
- [ ] No open pull request is intended for this release.
- [ ] The working tree is clean and every local branch that matters is merged.
- [ ] `v0.1.0` is still immutable — the annotated tag object and the commit it points
      at are unchanged:

      ```bash
      git rev-parse v0.1.0
      git rev-list -n 1 v0.1.0
      # expect 55329b5e378cb890c9b9775647396ea57fd7bdc7
      #    and ef98f962530fb62340cf213b408f1cd715755c01
      ```

## 2. Version and changelog

- [ ] `version` in the root `package.json`, `apps/api/package.json` and
      `packages/mcp-mongodb/package.json` is `0.2.0`.
- [ ] `SERVICE_VERSION` in `apps/api/src/routes/health.ts` and
      `MCP_SERVER_VERSION` in `packages/mcp-mongodb/src/tool-names.ts` are `0.2.0`.
      Both are reported by probes, so a stale value is visible to operators.
- [ ] `version` in `apps/console/pubspec.yaml` matches.
- [ ] `CHANGELOG.md` has a `## [0.2.0] - <date>` section, and `[Unreleased]` is empty
      apart from a fresh link definition.
- [ ] The changelog's entries match the release notes; nothing is in one and not the
      other.

## 3. Verification, run on the release commit

- [ ] `npm ci` from a clean checkout.
- [ ] `npm run build` — clean.
- [ ] `npm run typecheck` — clean.
- [ ] `npm test` — record the exact counts for API and MCP.
- [ ] `cd apps/console && flutter analyze && flutter test` — record the exact counts.
- [ ] `npm audit` and `npm audit --omit=dev --audit-level=high` — both clean.
- [ ] The dependency licence census is still all-permissive, with no GPL, AGPL, SSPL
      or BUSL. Record the counts.
- [ ] The documentation link and anchor audit resolves every relative link in every
      tracked `*.md`.
- [ ] Every file under `docs/` is linked from `docs/index.md`.

## 4. End-to-end, against a real stack

- [ ] A clean `docker compose up` starts MongoDB, the MCP adapter and the API.
- [ ] `GET /health` is `200` and `GET /ready` is `200` on a healthy stack.
- [ ] **Stop the MCP adapter: `GET /health` stays `200` and `GET /ready` becomes
      `503`.** This is the pair the readiness split exists for; verify it, do not
      assume it.
- [ ] `npm run migrate:dry-run` reports every migration applied on a fresh database
      after first start.
- [ ] Deploy a session, ingest telemetry, review it, terminate it.
- [ ] Restart the API and confirm the session's counters are unchanged.
- [ ] Re-send a batch and confirm `acceptedCount: 0` with the counters unchanged.
- [ ] `npm run backup`, then restore into a scratch database, and confirm the counts
      match the manifest.
- [ ] Rotate the API key using the overlap, and confirm the retired key is rejected
      once the overlap ends.
- [ ] `npm run bench` completes and the scaling table still plateaus.

## 5. Documentation

- [ ] The release notes are finalised against the tag commit: no "draft" banner, no
      forward references to work that did not land.
- [ ] [migration-v0.1-to-v0.2.md](../migration-v0.1-to-v0.2.md) is accurate.
- [ ] [compatibility.md](../compatibility.md) lists any new public contract, and its
      audit results are current.
- [ ] [security/threat-model.md](../security/threat-model.md) matches what the code
      does — re-read the limitations list, because a limitation that was fixed and
      left in place is as misleading as one that was introduced and not recorded.
- [ ] [development/maturity-plan.md](../development/maturity-plan.md) reflects the
      released state, and its exit-condition table has no "Not started" row.
- [ ] The README's quickstart works from a clean checkout. Run it.
- [ ] No document claims production readiness, compliance, or a guarantee the
      software does not provide.

## 6. Publish

- [ ] Create an **annotated** tag on the verified commit. Annotated, not lightweight:
      `v0.1.0` is annotated, and a lightweight tag would be a different kind of
      object for the same meaning.
- [ ] Push the tag.
- [ ] Create the GitHub Release from the release notes, marked pre-release unless
      step 0 decided otherwise.
- [ ] If a package or image is published, verify the published artefact independently
      — install it, or pull it, and run it. A local build is not a publication.
- [ ] Confirm the `v0.1.0` release and tag are untouched.

## 7. After

- [ ] Add a fresh `[Unreleased]` section to `CHANGELOG.md`.
- [ ] Record the release in
      [development/maturity-plan.md](../development/maturity-plan.md).
- [ ] Open the next phase's tracking issue, if there is one, rather than leaving the
      remaining open items implicit.

## Gates that are already met, and should not regress

Recorded here so the release run can confirm rather than rediscover them. Each was
verified during the operational-durability phase, with the evidence in the linked
document.

| Property | Evidence |
| --- | --- |
| A restart does not reset durable counters | [session-state-model.md](../development/session-state-model.md) — verified across a real process restart |
| A retry after a restart is stored and counted once | Unique `(sessionId, eventId)` identity; verified against real MongoDB across a restart |
| Migrations are ordered, idempotent and fail before mutating | `apps/api/test/migrations.test.ts`, plus a five-path drill against real MongoDB |
| Readiness distinguishes a dependency outage from a process failure | [operations/health-probes.md](../operations/health-probes.md) — verified with the adapter stopped |
| A backup restores to matching counts, or fails | [operations/backup-restore.md](../operations/backup-restore.md) — verified, including a tampered-manifest case |
| A key rotates without a cutover | [operations/key-rotation.md](../operations/key-rotation.md) — verified against real processes, both secrets |
| No dependency vulnerabilities | `npm audit`, both modes, clean |
| No new P0/P1 defect is known | [development/maturity-plan.md](../development/maturity-plan.md), with the open items named rather than omitted |
