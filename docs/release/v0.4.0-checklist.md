## 2a. Attribution and commit metadata

**A defect was found and is contained prospectively. Public history was not rewritten.**

**What was found.** Eleven commits — every commit merged after `v0.3.0`, PRs #49 to #59 —
carry:

```
Co-authored-by: Cerberus Maintainer <maintainer@cerberus.invalid>
```

**The scope is larger than a single commit.** An audit of the whole repository finds the
string `cerberus.invalid` in **exactly eleven** commits and in **no file in the tree**. None
predates `v0.3.0`.

**The cause, which is single and understood.** The feature-branch commits were created with
`git -c user.email=maintainer@cerberus.invalid`, so the commit's *author* was a synthetic
identity. GitHub's squash merge then recorded a `Co-authored-by` trailer for an author that
differed from the pull request's author.

**What is intact.** Every merge commit on `main` has author
`Muhammad Bilal Raza Lodhi <136831371+Bilal-Lodhi@users.noreply.github.com>` and committer
`GitHub <noreply@github.com>`. The authorship of the published history is the real identity;
only the message trailers carry the synthetic name. There are **no `Signed-off-by` trailers**
anywhere, and no other unexpected identity.

**Why it is not rewritten.** Rewriting a published branch is destructive, and the owner's
instruction is explicit: do not amend, rebase or force-push public `main`. The trailer is
recorded here instead, so it is a known, dated fact rather than a silent one.

**The prospective guard.** `npm run verify:attribution`
(`scripts/release/attribution-guard.mjs`) rejects, **in the commits being introduced only**:

1. an author, committer or trailer address in a **reserved domain** — `.invalid`, `.test`,
   `.localhost`, and the RFC 2606 documentation domains, none of which can belong to a real
   person;
2. an attribution trailer naming a **synthetic maintainer identity** by name, whatever its
   domain, so a future `.com` variant is caught too.

It **allows** legitimate external contributors and bot identities such as
`dependabot[bot]@users.noreply.github.com`. A name that is genuinely needed goes in
`scripts/release/attribution-allowlist.json` **with a reason**, so an exemption is a claim a
reviewer can check.

It is **prospective by construction**: it checks a range (`origin/main..HEAD` by default, an
explicit range in CI), so it passes on a history that already contains the eleven and fails
on a new one. `--all` is the diagnostic — it reports all eleven and exits non-zero — and is
deliberately not the gate.

**No further trailer of this kind has been added**, and none will be: the guard runs in CI
on every pull request and as a step in `npm run verify:release`.

**A false positive the guard found in itself, and the fix.** The first version matched
`^Co-authored-by:` anywhere in the message, and it therefore reported **the very commit that
introduced it** — the release-prep message quotes the trailer in its body prose. A guard
that cries wolf on prose is a guard that gets turned off. It now follows git's own rule and
reads only the **final paragraph**, the trailer block. Verified after the fix: the
release-prep range passes, `--all` still reports exactly eleven, and a genuine trailer block
naming the synthetic identity is still rejected.
