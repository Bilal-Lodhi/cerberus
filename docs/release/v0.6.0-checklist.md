# v0.6.0 release checklist

**Prepared, not executed.** Every gate below was run in this cycle and its result is recorded.
The publication steps at the end are **not run** and must not be run without a separate owner
decision.

The gates are `npm run verify:release` unless a row says otherwise. That command never publishes:
`scripts/release/secret-guards.mjs` fails the run if a publishing command appears anywhere under
`scripts/release/`.

## 5. Publication — **NOT RUN**

These are the steps a release decision would involve. They were not taken, and this document is
the record that they were not.

1. Confirm `main` is green on every required check.
2. Run `npm run verify:release` with a MongoDB available and confirm **0 failures, 0 skipped**.
3. Confirm the version census reports the intended version, and that `CHANGELOG.md` has an
   `[Unreleased]` section with no content destined for the next release.
4. Confirm the five published tag objects and targets are unchanged (§4).
5. Create an annotated `v0.6.0` tag on the verified commit.
6. Create a **GitHub pre-release**, never stable and never latest.
7. Do **not** publish an npm package, a container image, or a hosted deployment.

## 6. What must never happen in the publication step

- `npm publish` of any workspace package.
- A container image push to any registry.
- Marking the release stable or latest.
- Moving or recreating any existing tag.
- Rewriting public history to remove the recorded synthetic trailers.
- Publishing the console's built web bundle anywhere.
