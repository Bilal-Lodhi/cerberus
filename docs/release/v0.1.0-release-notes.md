# Cerberus v0.1.0 — First Independent Open-Source Release

**Status: draft release notes. This version has not been published.**

Cerberus 0.1.0 is the first release of Cerberus as an independent open-source
project. Cerberus began as "Cerberus FinSec", a Google Cloud / OpenAI hackathon
project built for the MongoDB partner track, and was subsequently extracted from
the historical `Google-Cloud-Hackathon` repository into this standalone
repository. This release is the state of that extraction: a self-hosted
telemetry service that ingests fine-grained terminal activity from a
browser-based operator console, scores it with a language model for
insider-threat and data-exfiltration indicators, and persists sessions, events
and risk assessments in MongoDB. It is an experimental research system, not a
compliance product, and it is not affiliated with, endorsed by, or sponsored by
Google, OpenAI or MongoDB.

## Highlights

- **API-key authentication** on the HTTP API, compared in constant time. The
  middleware accepts `Authorization: Bearer <key>` and `X-API-Key: <key>`,
  admits `GET /health` without a credential, and returns an identical
  `401 UNAUTHENTICATED` response for a missing and a mismatched key.
- **Explicit CORS allow-list.** Cross-origin access is granted only to origins
  named in `CERBERUS_CORS_ORIGINS`. The previous `origin: "*"` wildcard is gone;
  development-only localhost defaults apply only when `CERBERUS_DEV_MODE=true`.
- **Fail-closed configuration validation.** The API refuses to start when
  `OPENAI_API_KEY`, `CERBERUS_API_KEY` or `CERBERUS_MCP_TOKEN` is missing, and
  refuses to start with `CERBERUS_DEV_MODE=true` while `NODE_ENV=production`.
- **Micro-event telemetry ingestion** over `POST /api/v1/guardian/ingest`,
  covering twelve event types: keystrokes, paste triggers, code deltas, tab
  switches, window blur, copy attempts, dev-tools open, fullscreen exit,
  external app switch, submissions, edits and pastes.
- **Multi-layer deduplication** before inference is spent: identical
  risk-assessment id, code-hash equality to skip re-analysis of an unchanged
  workspace, a 128-entry micro-event fingerprint ring, and a behavioural-counter
  score blend.
- **AI risk analysis** producing a `RiskAssessmentPayload` with six risk
  dimensions, risk flags, an exfiltration report and behavioural anomalies.
- **Agentic auto-lock** at risk >= 75 and auto-clear below 25, propagated to
  in-memory session state and to MongoDB.
- **Threat scenario authoring** over `POST /api/v1/scenarios`, guarded by a
  deterministic regex pre-filter and a fail-closed AI classifier.
- **Session review** with a reconstructed event timeline and risk summary, plus
  session terminate (preserves data) and delete (removes data).
- **Natural-language auditor** over session records, restricted to a whitelisted
  subset of aggregation stages interpreted in-process.
- **MongoDB persistence through an MCP server**, with idempotent index creation
  and both a stdio transport and an HTTP adapter.
- **Automated test suite** using the Node.js built-in test runner (`node:test`)
  executed through `tsx`, wired up as `npm test`.
- **GitHub Actions continuous integration** covering the TypeScript workspaces,
  the Flutter console, the Docker image build, a secret scan and an advisory
  dependency audit.
- **Open-source documentation set**: `README.md`, `CONTRIBUTING.md`,
  `CODE_OF_CONDUCT.md`, `SECURITY.md`, `SUPPORT.md`, `CHANGELOG.md`, `NOTICE`,
  `docs/`, and the GitHub issue and pull request templates.
- **Docker Compose local startup** for the MongoDB dependency and the Cerberus
  services, and a multi-stage `Dockerfile` that runs both Node services in one
  non-root container.

## Breaking changes

This is the first release, so there is nothing to upgrade *from* within this
project's own release history. There is, however, **no upgrade path from the
hackathon-era code or data.** The historical names are not accepted as aliases,
fallbacks or compatibility shims: there is no dual-write path, no read-through of
legacy documents, no route alias and no feature flag that restores the old
behaviour. Data and client code that use the historical names must be renamed
before Cerberus 0.1.0 can read it. The full mapping, plus the rename sequence and
its risks, is in [`docs/migration.md`](../migration.md).

### Removed Assessment-era type aliases

The Assessment-era type-alias layer that duplicated the domain types has been
removed, together with the legacy `GeminiClient` class name (replaced by
`OpenAIProvider`), hackathon-only files, tracked build artifacts and unrelated
cloud-project identifiers. Code that imported those aliases or that class must
import the domain types from `apps/api/src/types.ts` and the provider from
`apps/api/src/ai/provider.ts`.

## Security

- **API-key authentication with constant-time comparison.** The presented
  credential is compared against `CERBERUS_API_KEY` using
  `crypto.timingSafeEqual`, without short-circuiting on length. A missing
  credential and a mismatched credential return the same `401 UNAUTHENTICATED`
  body, so the response does not reveal which case occurred. The MCP adapter
  likewise requires `CERBERUS_MCP_TOKEN` and binds to loopback by default.
- **Explicit CORS allow-list.** The `origin: "*"` wildcard was removed.
  Cross-origin access requires an entry in `CERBERUS_CORS_ORIGINS`; with no
  allow-list and no development mode, no cross-origin access is granted.
- **Fail-closed configuration validation.** Mandatory secrets are validated once
  at startup, and the process exits rather than booting into an unauthenticated
  or half-configured state. `CERBERUS_DEV_MODE=true` is refused outright when
  `NODE_ENV=production`. The container entrypoint applies the same check for
  `NODE_ENV=production` with an unset `CERBERUS_API_KEY`.
- **Secrets removed from startup logs.** The configuration banner and the
  service banner report only whether each credential is `set` or `unset`. No key
  material is written to logs or returned in error responses; the global error
  handler returns a stable `INTERNAL_ERROR` code with a correlation id instead of
  framework, provider or database internals.
- **Repository hygiene.** CI scans for verified secrets, rejects committed
  credential-shaped files (`.env`, `application_default_credentials.json`,
  `*.pem`, `*.key`) and fails if a retired deployment or product identifier is
  present.

## Known limitations

These are properties of the release, not defects to be discovered later. Do not
deploy Cerberus expecting them to be absent.

- **Not production ready.** Cerberus is an experimental research system. It has
  no release history, no stability guarantee and no support contract.
- **No guarantee of detection or prevention.** Cerberus makes no claim that it
  will detect, prevent, or prove any particular activity. Treat its output as a
  risk signal for human review, not as evidence or as an authoritative decision.
- **A single shared API key, with no per-user attribution.** There is no user
  directory, no roles and no OAuth/SSO. Cerberus cannot tell two operators apart,
  and revoking one operator's access means rotating the key for everyone.
- **In-memory session state is lost on restart.** Live session state is held in
  process memory. MongoDB is a durable fallback for counters and review data, but
  the authoritative live state does not survive a restart.
- **Reference completions are not populated, so similarity matching returns no
  matches.** `DATA_LEAKAGE_SIMILARITY_THRESHOLD` is read from configuration and
  carried into the analysis prompt, but the reference-completion source returns an
  empty set, so `ExfiltrationReport.matchedSnippets` is always empty.
- **The endpoint agent is not built.** The process that would emit telemetry from
  a real workstation does not exist. All telemetry today originates from the
  browser-based console.
- **No rate limiting.** The API does not throttle requests, and there is no
  replay protection beyond TLS.
- **Manual key rotation only.** There is no automated rotation and no overlap
  window: the API accepts exactly one key at a time, so rotation is a brief
  outage for clients that have not yet been updated.
- **Telemetry can contain sensitive content.** `codeSnapshot`, `pasteSnippets`,
  `copyContent` and `terminalSnapshot` capture whatever was in the monitored
  workspace or clipboard, which may include secrets, customer data or third-party
  material. Monitoring people may require notice, consent or consultation with an
  employee representative body depending on your jurisdiction, and processing
  this data is likely to engage data-protection law. See
  [`SECURITY.md`](../../SECURITY.md) and
  [`docs/security/threat-model.md`](../security/threat-model.md).
